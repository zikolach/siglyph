# Design

`submittedText` delegates directly to `buffer.submitText` under the component state boundary. It changes no buffer, cursor, registry, undo, history, autocomplete, callbacks, or submission state. Callers validate this value before clearing/replacing/queueing the editor.

`EditorDraftSnapshot` is a sealed opaque interface with no public constructor, members, copy or product methods. A private implementation keeps saved state without a state getter on the public interface. Scala package-scoped internal bridges are implementation details, not a security boundary against JVM reflection or Java access. Restore validates the captured value (including null rejection) before any mutation. It wraps the actual immutable `EditorBuffer.Snapshot` (persistent Vector/Map, cursor, paste counter); it does not reconstruct state from displayed strings. Values are detached, reusable and transferable between editors, not serialized editor checkpoints.

Both reads observe only committed buffer contents. Pending `PasteStart`/`PasteChunk` data remains uncommitted and excluded; neither accessor completes or cancels that session. Restore discards an in-progress paste, so later chunks/end cannot leak it into the restored draft.

Restore atomically restores lines, registry, identity counter and exact logical cursor; clears undo and yank continuation, jump mode, preferred column and history browsing; retains history entries, kill ring, callbacks, focus, configuration and TUI context. It cancels/invalidate autocomplete work and closes its UI without refreshing. It invalidates layout and requests render. `onChange` receives displayed text once only if displayed or submitted content differs; cursor-only/no-op restores emit no change. No submit callback runs. All external effects execute after releasing the state boundary, following existing Editor transitions.

This deliberately does not preserve undo history or pending async handles: replaying those against another draft could overwrite restored content. Marker-looking literal strings are not a substitute for the opaque snapshot. Marker expansion is single-pass and replacement-safe; allocation avoids IDs already present in displayed literals, stored payloads or the incoming payload, with overflow-safe parsing. The existing Snapshot shape is preserved. Literal text identical to an already registered marker inserted later retains legacy alias semantics; distinguishing that case requires a broader structural span-provenance model and is not promised here. Public draft APIs do not expose editable registry state.
